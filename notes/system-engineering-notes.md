# System Engineering Notes

## Requirement Specification

### System Context

The purpose of the System Context section is to identify the major elements that interact with the system and describe those interactions at a high level.
The key question being answered is:
"Who or what exists outside the system, and how do they interact with it?"
Examples may include:

Homeowner
Mobile Application
Door Sensor
Motion Sensor
Cloud Service

The System Context provides a black-box view of the system. At this stage, the focus is on external actors, external systems, and interfaces crossing the system boundary rather than the internal implementation of the system.
The objective is to understand the operational environment of the system and its relationships with surrounding elements.

### System Design
The purpose of the System Design phase is to define how the system will be built to satisfy the requirements.
The key question being answered is:
"How will the system be implemented?"
This stage typically includes:

Component Diagrams
Logical Architecture
Physical Architecture
Sensor Subsystems
Communication Modules
Alert Management Components

Unlike the System Context, System Design examines the internal structure of the system and describes how different components interact to fulfill the specified requirements.
The focus shifts from understanding the system's environment to defining the architecture and implementation approach required to realize the system.
